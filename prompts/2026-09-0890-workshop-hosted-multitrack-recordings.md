[✨📦] Upload and publish a hosted synchronized recording for a workshop

- Add a per-workshop video-source choice in `/admin/workshops`: existing YouTube video OR a hosted multi-track recording. Keep every existing workshop on YouTube by default, with its URL, start offset, teaser, stage placement and access behavior unchanged. Switching sources must preserve the inactive configuration. Never require hosted tracks for a YouTube-only workshop.
- Accept separately recorded synchronized `editor` (VS Code), `application` (application screen), and `camera` files, their audio, optional subtitle sidecars and the versioned manifest/activity/event/commit metadata from [the studio timeline PRD](2026-09-0880-studio-workshop-timeline-metadata.md). Provide both a direct admin upload of independent files/sidecars and an explicit `Publish to workshop` action from [the studio editor](2026-09-0850-studio-synchronized-editor.md). The studio connection is a convenience: already exported files must be importable without a studio project or browser-local storage.
- Validate track roles, content type, duration and session/export timestamps. Support missing optional screen track with an honest disabled tab, but require at least one playable video and a usable session clock. Show a preview and validation report before publication; fail publication on materially misaligned tracks, malformed sidecars, unknown timing coordinates or an unusable media file. A subtitle file is imported for metadata/export compatibility and is not displayed in the participant player.
- Store media in durable server-accessible object storage appropriate for large, multi-hour videos. Use resumable/chunked uploads, progress, retry and cancellation, bounded memory, integrity checks and a processing/publishing state. Browser-local studio storage cannot be the participant delivery source. Keep previous published revision available until the new revision is verified and atomically published; do not expose partial uploads. Provide a safe replacement/removal workflow and clean up abandoned uploads without removing a published asset.
- Serve the media with byte-range seeking and formats/codecs supported by target browsers, or process it into suitable streaming renditions. Preserve synchronization and the shared duration during transcode. Restrict upload, publication and deletion to admins. Authorize every manifest, track, range/segment and rendition request using the same server-side room and membership rules as `lib/workshops/workshopPaidMembersVideo.ts`; a hidden URL is not access control. Use bounded, expiring delivery credentials where appropriate and do not leak a paid recording through room JSON, material previews, exports, cache or public storage URLs.
- Keep live/free access during the workshop and the existing paid replay gate after it ends. Preserve the same wrap-up, teaser/offer and special-material behavior whether video is primary or supplementary. The existing YouTube teaser can remain the preview; no teaser still yields the current generic membership offer. Keep the recording start offset semantics explicit for imported files: avoid applying a YouTube offset a second time to prepared media; map live start/end to the hosted session clock deliberately.
- Start by inspecting `WorkshopSettingsForm.tsx`, `WorkshopStage.tsx`, `WorkshopVideoMaterial.tsx`, `workshopSpecialMaterials.ts`, `workshopPaidMembersVideo.ts`, workshop schemas/types and the recording studio's storage/export code. Reuse existing migrations and authorization patterns.
- Acceptance criteria:
    - Import independent files and sidecars, then publish them; separately publish the same type of project directly from the studio. Both survive a different device and a server restart.
    - Replace a recording while viewers are connected; they receive a consistent published revision, not mixed old/new tracks. Interrupted and invalid uploads leave the old revision intact.
    - Existing YouTube workshops behave as before. A free participant can watch the hosted workshop live, but after it ends only a paying member can fetch any recording bytes or protected metadata, including guessed range URLs.
- Keep in mind the DRY _(don't repeat yourself)_ principle. Share video-source selection and gating across stage, materials and wrap-up.
- Do an analysis of the current functionality before you start implementing.
- Add the changes into the [changelog](../changelog/_current-preversion.md).
