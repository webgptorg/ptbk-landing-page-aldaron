# Recording studio workshop metadata

## Existing functionality before this change

The recording editor stores camera, screen and microphone media as independent local tracks. Each pause closes a playable media part; an appended take starts new parts at the next recorded-content session second. `RecordingStudioTransport`, the timeline, saved IN/OUT selection and `RecordingEditRecipe` already use that one session clock. ZIP export keeps original parts and prepares individual source files only where a selection fits a decodable part. Manifest schema 4 and the subtitle/speech sidecars already describe their original and prepared coordinates. Subtitle generation and local voice activity detection store independent, editable revisions, but neither decides what the workshop player should speed up or which picture it should show. The editor had no workshop events, Auto-view decisions or calibrated time-to-SHA anchors.

## Local editing and review

`StudioRecording.workshopMetadata` is an optional browser-local revision of workshop annotations. Existing recordings remain readable without it. The editor creates it explicitly and autosaves it through the same protected recording edit. Both IndexedDB and selected-directory checkpoints retain the complete metadata on reload or read-only folder import. Manual changes survive transcript or voice activity regeneration because those tracks remain separate. An appended take extends the activity coverage with an unclassified range and makes the saved source revision stale; the editor keeps earlier work and offers explicit revision review.

Activity intervals use half-open original session ranges, never overlap, and cover the selected export. The initial full-session interval is `unclassified`. Splitting, moving a shared boundary, merging and reclassifying are non-destructive. A speech track can split unclassified ranges at detected speech boundaries but assigns no playback class. Suggested boundaries retain the speech track, audio source and media revision even after manual correction. In particular, silence and uncertain audio never imply `automatic-coding`. That class requires an explicit review checkbox; unclassified time has a specified 1× playback rate. Event markers have a title, optional type/detail and independent time. Editing their times sorts them; they never alter media, activity or subtitle cues.

Auto-view stores a default `editor` or `application` scene and reviewed transition points. Each scene names one of the original video source IDs. Validation checks that the chosen source covers the entire selected scene span using the existing source segment and measured video-component ranges; an audio-only part does not count as a valid picture. A missing source or gap blocks workshop metadata export; the original source files remain independent and Auto-view never changes them.

## Git association and calibration

The editor stores the repository identity, selected branch patterns and a verified 40-character starting SHA. Manual anchors resolve through the existing authenticated workshop commit lookup, which checks the selected branches. The editor can recheck saved SHA references. A failed provider check becomes `unverified`, so playback reports `unknown` rather than claiming that GitHub proved a commit missing; after confirming a missing or rebased commit, the editor can explicitly mark it `unavailable`. Lookup at or after an unavailable anchor reports unavailable until another reviewed anchor takes over. Before the first anchor, the starting commit applies. It never creates a SHA from a date.

Automatic proposals require an explicit calibration pair: a recorded-content session second and an ISO wall-clock timestamp with an offset or `Z`. The authenticated proposal endpoint reads only actual commits from the selected branches within the calibrated window, with bounded pages and count. Their commit timestamps suggest positions; proposals are stored unreviewed until an editor checks each against the recording. One calibration cannot account for a pause or a later appended take, so its proposed times are especially approximate across those boundaries; the editor must move or discard them after review. The UI calls out timezone, clock skew, delayed pushes, rebases and uncommitted work. A truncated feed reports that its proposal list is incomplete. Start/anchor availability records the last check attempt; rechecking before publication is the operator's way to detect later branch changes.

## Versioned export contract

Manifest schema 5 lists workshop original and prepared JSON sidecars separately, along with saved/current media revisions and a stale flag. It also embeds the original workshop data, including original coordinates and provenance, in ZIP and standalone manifests. Workshop sidecar schema 1 includes the source recording ID, source revision, repository/branches, starting SHA, calibration, activities, events, scene source choices/transitions, commit anchors and the existing edit recipe. Original sidecars use original session seconds. Prepared sidecars clip crossing activity ranges, omit outside events/points and subtract `editRecipe.preparedTimeZeroSessionSeconds`; each emitted item also carries its original coordinate. `commitAtSelectionStart` preserves the last reliable SHA state when earlier anchors fall outside the selection. Every prepared source receives the same global workshop sidecar and zero. A source that cannot be transcoded remains an original plus recipe, with its fallback clearly recorded in the manifest.

Export validates positive bounded intervals, selected-range coverage, no activity overlap, reviewed automatic coding, reviewed scene transitions, scene source availability, bounded markers and full SHA references before writing an archive or prepared media. Transcript text remains an editorial input and is not declared visible player subtitles. This task exports metadata and media files locally; it does not upload or publish them.

## Verification limits

Unit coverage uses two video sources, independently playable parts, a global pause and an appended take. It checks clip/rebase alignment, manual interval operations, speech suggestions without inferred coding, scene gaps, stale revision reporting and commit lookup around anchors. Archive tests check schema and sidecar inclusion. A browser test exports three real prepared files from an appended take and checks their shared zero against events, activity, scene changes and Git anchors. Physical capture timing and the accuracy of commit dates still require review against the actual workshop recording.
