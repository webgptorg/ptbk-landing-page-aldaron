# Recording studio subtitle and speech activity tracks

## Analysis of the existing editor

The synchronized editor already keeps each camera, screen and microphone as an independent browser-local media source. `RecordingMediaPart` and its segments map source timestamps to the recorded-content session clock. A global pause closes parts and removes paused wall time; appended takes add parts without changing earlier media. `RecordingStudioTransport` owns playback and seeking, while `RecordingTimeline` and `RecordingEditor` use the same session seconds. The saved IN/OUT selection is one `RecordingEditRecipe` for all sources. ZIP export retains original parts and prepares a separate file per source only when that selection fits one decodable part.

The workshop subtitle feature already had bounded 16 kHz WAV conversion, an authenticated admin route, the shared private OpenAI transcription client, Czech/English/mixed language handling, and SRT/WebVTT serialization. It did not operate on browser-local studio parts or store studio edits. The studio had no speech activity detector. Studio metadata is stored with its recording in IndexedDB or the selected recording directory, so a separate database or remote job store would duplicate the local recording's ownership and recovery behavior.

## Derived track contract

- Generation is available only for a completed recording and starts only from its explicit button. Camera, screen and microphone sources with measured component bounds are eligible only when an audio component is present. For older records without those bounds, the editor checks each candidate's stored media locally before enabling it, even if its saved audio flag is wrong in either direction. A video-only source cannot be selected. The generator rechecks the actual decoder before processing.
- Every request selects one source ID. The generated track records the source label, a SHA-256 revision of committed media/take/segment metadata, creation time, language where applicable, processor and settings. A changed source or appended take makes old revisions visibly stale. Regeneration creates another track; manual cues and interval corrections stay in their earlier revision.
- The browser converts one 70-second window at a time to mono 16 kHz WAV. Adjacent windows overlap by 1.5 seconds. Returned cue times are clipped to the decoded slice and mapped through the part's source-to-session segments exactly once. Every returned cue is retained before reconciliation so a cue recognized by only one neighboring window cannot disappear at the ownership boundary. Substantially overlapping copies and contained phrases are reconciled; different words are retained for review.
- Subtitle WAV chunks go through `/api/admin/recording-studio/transcribe`, which checks the admin session and the existing file/language limits and calls the shared OpenAI transcription utility with the server's existing `OPENAI_API_KEY`. The button explains this transfer before it occurs. The browser never receives the key and opening the editor sends no recorded audio.
- Speech activity uses the locally served Silero legacy VAD model through ONNX Runtime in the browser. Positive/negative thresholds, minimum speech duration, redemption, pre-roll, and the uncertainty energy floor are recorded with the track. The energy check can only mark unresolved sound **uncertain**; it cannot label sound as speech. Detector output has no calibrated confidence, so generated events carry no invented confidence. Music, noise, breath and quiet speech need listening review; “silence” means no speech was recognized in captured audio, not proof that the microphone signal was digitally zero.
- Activity intervals cover the selected source's session duration with `speech`, `silence`, `uncertain` and `unknown`. Missing/undecodable source audio is `unknown`, including when no committed audio part can be read; a global pause has no session interval at all. Subtitles report an actionable failure when no audio can be read. Speech start/end events are derived from adjacent speech intervals, not stored as a second competing transcript. Manual interval correction removes overlap and records manual origin.
- Derived lanes share the raw timeline's playhead and zoom. Hiding a lane only changes the display. The subtitle editor previews the active cue; both editors use the existing recording autosave, navigation protection and undo controls.

## Sidecars and coordinates

The ZIP keeps `metadata/original/` next to unmodified source files. For a source that really produced a prepared media file, it also includes `metadata/prepared/`. Individual original/prepared downloads emit that source's sidecars. Filenames carry the recording stem, source number, source ID, kind and stable derived track ID. SRT and WebVTT contain enabled text cues; subtitle JSON also retains disabled cues and manual provenance. Speech activity JSON contains intervals and derived boundaries; CSV has source ID, type, seconds, confidence only when available, origin, coordinate, processor, revision and settings. All are UTF-8.

Original sidecars use **original session seconds**. Prepared sidecars clip every cue/interval to the same saved IN/OUT selection as media export and subtract the selection start. Out-of-range entries are omitted; cues crossing either edge are clipped. SRT/WebVTT cue times are rounded to milliseconds with a minimum one-millisecond positive duration. JSON speech boundaries carry the same `startSeconds`/`endSeconds` fields as intervals, equal at each point event. No subtitle is burned into video and no activity interval edits or cuts media. Manifest schema 4 lists original and prepared sidecars separately, the media preparation status for each source, the shared recipe and its prepared zero.

## Verification and remaining platform checks

Unit tests cover source eligibility, part-to-session mapping, unavailable audio, uncertainty without fabricated speech confidence, cue reconciliation, edit overlap, original/prepared SRT/WebVTT/JSON/CSV coordinates, and archive fallback when a selection crosses media parts. The browser tests use actual local WebM fixtures, a generated 75-second WAV, browser decoding and the local VAD. They stub only the external transcription response to verify selected-source WAV requests, Czech cue placement and a cue returned by only one overlapping chunk without activating a paid account. They also check that a legacy video-only file stays disabled even when its saved flag incorrectly claims audio. The studio unit suite passed 118 tests, the production build and TypeScript check passed, and five targeted browser cases passed in Windows Chromium on 2026-09-29.

For a local model reference on Windows, the installed Czech `Microsoft Jakub` voice synthesized “Dobrý den. Toto je zkouška české řeči.” to PCM WAV. One second of digital silence was prepended. At a 10 ms RMS ground-truth threshold of 0.001, audible speech began near 1.110 s and ended near 4.412 s. Silero VAD returned 1.152–2.208 s and 2.592–4.896 s: first-onset error about +42 ms and final-end error about +484 ms, including the configured 500 ms redemption. At 10% volume it returned 1.344–5.472 s, giving about +234 ms onset and +1.060 s end error. Separate three-second digitally silent, two-tone music, seeded noise and filtered breath-like noise samples each returned zero speech events; the non-silent samples are eligible for `uncertain`, never promoted to speech by energy. These are measured results for one synthetic voice and this model/settings, not accuracy claims for people or rooms. The temporary synthesized WAV was not added to the repository.

The checked-in browser fixture contains timecodes and audio claps, not spoken Czech or representative music/room noise. Word recognition accuracy and VAD boundary error on real Czech speech, quiet speech, breath, noise and music still require a consented reference recording with known boundaries. The owner's physical macOS camera/screen/microphone workflow, including native picker and pause/append capture, likewise requires that machine; browser automation cannot certify it. On that machine, create a short reference with spoken Czech and recorded boundary timestamps, then run both generators independently on embedded camera audio and a standalone microphone, check the measured start/end error and uncertain/unknown labels, correct and regenerate a cue, pause/append a take, and compare each prepared source and sidecar at trim boundaries. Repeat the supported browser path on Windows/Edge and the available other platforms.
